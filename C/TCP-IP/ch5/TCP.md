# TCP의 이론적인 이야기
## TCP의 입출력 버퍼
- 서버가 패킷으로 나누어 데이터를 전송할 때 남은 패킷들은 어디에 있을까?
- 사실 write 함수가 호출되면 데이터는 출력 버퍼로 이동하게 된다.
- read 함수가 호출되면 입력 버퍼에 저장된 데이터를 읽어들인다
- 입출력 버퍼는 다음과 같은 특징을 가지고 있다
  1. 입출력 버퍼는 각각의 소켓에 별도로 생성된다.
  2. 소켓 생성시 자동으로 생성된다
  3. 소켓을 닫아도 출력버퍼의 남은 데이터는 전송이 이루어진다
  4. 소켓을 닫으면 입력 버퍼의 남은 데이터는 사라진다
---
- TCP에는 슬라이딩 윈도우라는 프로토콜이 존재함
- 서로 대화를 주고받으며 입력버퍼의 크기의 정보를 알려줌
- 입력버퍼의 크기를 초과하는 분량의 데이터 전송은 일어나지 않음
## 상대 소켓과의 연결
- 소켓간의 소통은 3단계로 이루어진다
 1. 연결 요청
 2. 연결 허가
 3. 연결 종료
- 실질적으로 컴퓨터가 보내는 메시지는 이렇게 되어있다
| SEQ | ACK | 메시지 의미 |
| --- | --- | --- |
| 1000 | - | 1000번 패킷 전송, 수신 양호시 1001번 패킷 송신 요망 |
| 2000 | 1001 | 2000번 패킷 전송, 수신 양호시 2001번 패킷 송신 요망, 다음 송신은 1001 패킷 송신 요망 |
| 1001 | 2001 | 1000번 패킷 전송, 다음 송신은 2001 패킷 송신 요망 | 
---
- ACK번호는 다음과 같은 공식을 기준으로 전송함
```
ACK = SEQ + 전송된 바이트 크기 + 1
```
- 상대 소켓과 의 연결 종료는 전송하는 패킷에 FIN메시지를 전송 함으로써 이루어진다
